# 本地存储

固件将长期设置与运行状态分开管理。页面读取内存中的配置缓存，修改设置时通过统一存储接口提交，避免各页面自行操作 NVS。

## 存储位置

| 内容 | 位置与实现 |
| --- | --- |
| 显示、声音、电源、输入设备等设置 | `app_nvs` 分区，由 `main/app/storage` 管理 |
| WLAN 偏好与已保存网络 | 配置缓存和 TLV 记录，最多 10 份网络凭据 |
| 应用自动连接与授权 | `app_nvs` 中 `settings` 命名空间的 `app_connections` 记录，最多 5 份凭据 |
| TLS 设备身份 | `app_nvs` 中 `app_tls` 命名空间的 `identity_v1` 记录 |
| Radio 聊天等文件数据 | `storage` 分区中的 LittleFS，设备内挂载点为 `/littlefs` |

这些是设备 Flash 分区、NVS 名称和固件内挂载点，不是桌面应用的文件保存目录。分区由 [partitions_esp32p4.csv](../partitions_esp32p4.csv) 定义。

## 配置缓存与 TLV

主要设置域使用 TLV（类型、长度、值）格式，由 [tlv_storage.h](../main/app/storage/tlv_storage.h) 定义公共接口。各模块负责读取、范围校验和默认值。

新增配置时：

1. 在所属存储模块定义字段和默认值。
2. 分配稳定的域编号和字段标签，已发布编号不改号、不复用。
3. 对缺失字段提供合理默认值，对读取和更新后的值做范围校验。
4. 保持已有字段的含义和数据类型，结构变更时明确兼容策略。
5. 通过现有缓存及持久化接口更新，不在 LVGL 高频定时器中直接写 Flash。

TLV 能帮助兼容新增字段，但不能自动解决改号、改类型或错误的迁移代码。首次启动记录、TLS 身份等应按各自模块的格式处理，不能假定所有存储都是同一种 TLV 结构。

## 生命周期与恢复

[storage.cpp](../main/app/storage/storage.cpp) 负责初始化配置缓存，并在关机前通过 `FlushPendingStorageBeforeShutdown` 尝试提交待保存内容。保存失败需要沿用模块的错误处理，不能只更新界面并假定已经写入成功。

正常、保留分区的固件升级通常会保留设置。擦除 Flash、变更分区布局或恢复出厂设置会影响这些数据。恢复出厂设置会清除 NVS 和 LittleFS，设备证书及授权也随之删除，桌面应用需要重新配对。

NVS 初始化异常及损坏记录有各自恢复策略，因此不能承诺任意损坏或升级情况下都不丢数据。新增存储功能时应验证旧记录读取、缺失字段、非法内容和保存失败。

应用密钥和 TLS 私钥属于敏感数据，不写入普通日志，也不将实际存储内容加入仓库。
