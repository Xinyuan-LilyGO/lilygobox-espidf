# LilygoBox 应用连接

设备通过局域网 Wi-Fi 与 LilygoBox 桌面应用连接，不依赖公网账号服务。设备页面负责授权、自动连接开关和凭据管理；网络服务的生命周期独立于页面。

## 使用流程

1. 设备与桌面应用加入能够相互访问的局域网。
2. 在设备的“更多连接 → LilygoBox 应用”中开启自动连接。Wi-Fi 未开启时，页面提示先开启 Wi-Fi。
3. 桌面应用发现设备并发起连接，设备首次弹出授权确认。
4. 同意后双方保存凭据，后续重连不重复询问。

设备最多保存 5 个应用凭据，同时只允许一个应用处于连接状态。授权应用列表支持拖动排序，顺序决定自动重连优先级。

桌面端删除设备后再次添加，仍需在设备端确认。确认后按桌面应用的稳定 `clientId` 更新原授权并轮换密钥，保留原有排序，不新增名额；即使五个名额已满，同一应用仍可更新自己的凭据。不同应用安装即使电脑名称相同，也不会合并。拒绝、超时或保存失败不会替换原记录。

“当前连接”中的断开操作需要确认，并保留凭据；它也会暂停该连接的自动恢复，避免用户刚断开就立即连回。删除授权需要确认，会撤销凭据并断开对应连接。

## 发现与通信

| 项目 | 当前约定 |
| --- | --- |
| 局域网发现 | UDP，端口 `18463` |
| 发现消息 | `lilygobox.discover`，响应 `lilygobox.device` |
| 连接传输 | TLS 加密的 WebSocket，端口 `18464` |
| WebSocket 路径 | `/api/v1/ws` |
| 消息格式 | UTF-8 JSON，协议版本 `1`，配对版本 `2` |
| 消息长度限制 | 1024 字节 |
| 保活 | 客户端约每 5 秒发送心跳，设备约 15 秒未收到有效保活则超时 |

发现请求携带随机 nonce，响应回传 nonce，并提供设备名称、型号、固件版本及连接端口。设备标识来自基础 MAC 的 12 位十六进制表示；界面可显示格式化 MAC 以帮助区分设备，名称不作为授权身份。

首次连接经历 `hello → waiting → poll → ready`，授权等待上限为 60 秒。只有进入 `ready` 才视为业务连接建立，WebSocket 建立本身不代表已获授权。

已授权应用使用挑战应答恢复连接。设备在约 4 秒的候选窗口中按凭据顺序选择可用应用；更高优先级的应用不会抢占已经建立的连接。

## 安全与存储

- 设备生成并保存 ECDSA P-256 自签名证书，WebSocket 数据通过 TLS 加密。
- 首次授权后，桌面应用保存设备证书 SHA-256 指纹，后续验证指纹。
- 每份授权使用独立的 256 位随机密钥；重连通过 HMAC-SHA256 挑战应答验证，不直接发送长期密钥。
- `clientId` 是独立于配对密钥的 64 字符小写十六进制安装标识，只用于人工确认后的去重，不能作为授权证明。桌面端删除设备时保留它；重连仍必须验证 HMAC。
- 凭据内层 TLV 新增可选字段 `clientId=4`，原有字段编号不变。旧记录在一次成功的密钥认证重连后补记安装标识；升级两端后建议先正常重连，再测试删除和重新添加。无法验证归属的历史同名记录需手动删除，不按名称自动合并。
- 授权凭据和证书身份保存在 `app_nvs` 分区，见[本地存储](local-storage.md)。

首次信任仍依赖可信局域网和用户确认。TLS 保护传输过程，并不意味着设备 Flash 已加密；密钥及私钥不得输出到普通日志或加入仓库。

## 设备状态与控制

已授权会话通过同一 WSS 通道传输控制 JSON，解析使用 ESP-IDF 的 cJSON。`ready` 和 `pong` 包含 `controlVersion: 1` 与 `state` 快照；客户端每秒发送 `state.get` 获取 `state` 响应。本地设置的更新也会出现在后续快照中。旧固件不提供控制版本时，桌面保留连接但禁用控制。

`state.ready` 表示应用已完成启动。`capabilities.screen/audio/haptic` 表示当前设备提供的控制接口；不支持的控制不能提交。电池复用现有状态采集，不在网络回调中访问 I2C。`battery.available` 为 false 时不提供虚构读数；有效电池包含 percent、charging、full、voltageMv、currentMa、temperatureC。

命令示例：

```json
{"v":1,"type":"control.set","requestId":1,"field":"brightness","value":75}
```

| 字段 | 目标值 | 行为 |
| --- | --- | --- |
| screenEnabled | boolean | 通过锁屏任务执行熄屏或唤醒，不远程解锁 |
| brightness | 10–100 整数 | 保存目标亮度；熄屏时保持关闭，唤醒后恢复 |
| rotation | 0 / 90 / 180 / 270 | 保存并应用显示旋转 |
| lockTimeoutSeconds | 15 / 30 / 60 / 120 / 300 / 600 / 0 | 保存自动锁屏等待秒数，0 表示永不；不主动解锁或唤醒 |
| soundEnabled | boolean | 静音保留音量，开关仅在本次运行期间保留 |
| volume | 0–100 整数 | 通过共用音频入口执行并保存音量 |
| hapticEnabled | boolean | 保存系统触感开关，保留强度 |
| hapticStrength | 0–100 整数 | 保存系统触感强度 |

设备先响应 `control.queued`；桌面约每 150ms 发送带相同 requestId 的 `control.poll`，直到收到 `control.result`。结果包含 requestId、ok、error 和 state。只有实际硬件调用与所需存储提交成功才返回 ok；触感控制更新的是系统反馈配置，不自动播放振动。旋转使用现有 LVGL 显示接口。

每个会话只允许一条执行中的命令。请求编号为 1–2147483647 的递增整数，同编号重试不重复执行；旧编号拒绝执行。未开始的请求 5 秒后过期。会话断开后尚未执行的命令与旧结果不用于新连接；已开始的硬件调用可能完成，重连后需重新读取实际状态。

桌面滑条采用 180ms 尾沿合并，串行提交最新目标，避免每次鼠标事件写入 NVS。结果失败时恢复设备确认值；10 秒未取得结果则结束会话，重新同步后再允许控制。离线保留最近快照，但禁止发送控制，也不在重连时重放旧目标。错误只用于调试输出，当前不添加生产通知。

网络任务仅校验、入队和返回缓存，不持有会话锁执行硬件操作。屏幕开关复用锁屏任务；其他控制由应用主循环执行。投屏等大数据功能需另设资源限制，不能塞入当前 1024 字节控制消息。

## 回归检查

- 同一桌面应用反复删除设备、重新添加并确认，凭据数量和排序应不变。
- 五份凭据满额时，已有应用可重新配对；新的第六个应用不可添加。
- 拒绝重新配对或存储失败后，旧凭据仍保留；确认成功后旧密钥失效。
- 相同电脑名称、不同安装标识应生成两份独立凭据。
- 普通断线、应用重启和设备重启仍可自动重连，无需重复确认。

## 屏幕旋转与页面退出

本地设置和桌面控制共用显示旋转入口。根屏幕尺寸事件只提交合并后的异步重排，事件分发结束后才销毁页面，避免在控件回调中删除正在使用的对象。旋转后关闭当前应用、子页和弹窗，统一返回设备主界面，不重建原应用或恢复导航层级；180° 旋转即使尺寸未改变也执行相同流程。启动引导仍保留其启动流程。

设备处于锁屏时，旋转保持锁屏覆盖并更新布局，不发送解锁通知。新锁屏创建失败时继续保留旧锁屏。桌面应用发送旋转控制前弹出确认框，说明设备返回主界面、未保存内容不会保留及锁屏保持规则；取消不发送命令。

WLAN 扫描快照和设置页状态使用 PSRAM，普通 UI 分配在内部堆余量不足时转向 PSRAM。关闭 UI 不停止全局 Wi-Fi、桌面连接和固件更新服务。TLS/AES 或 SDIO 分配失败时，应检查内部堆余量及最大连续块；PSRAM 总余量不能代表内部 DMA 缓冲仍然可用。


设备默认名称采用 `LilygoBox_AABBCCDDEEFF` 格式，MAC 使用本机基础 MAC。默认名称在启动时生成，不额外写入存储。用户在设备设置中修改名称后，通过统一 NVS 事务保存到 `app_nvs` 分区的 `settings/device_name`，重启优先恢复用户名称；恢复出厂设置后重新使用默认名称。发现响应及连接状态同步使用同一名称，名称变化不影响设备 ID 和连接凭证。
